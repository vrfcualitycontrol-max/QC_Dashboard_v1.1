# Правила работы с аналитическим дашбордом Soft Collection (Quality Control)

Это жесткие правила (библия) по работе с проектом. Перед любыми изменениями кода необходимо строго сверяться с этим документом!

## 1. БЕЗОПАСНОСТЬ И ХИРУРГИЯ КОДА (Файл 400 Кб)
* **Никогда** не переписывай `index.html` целиком!
* Все обновления JSON-данных делай снайперски: используй регулярные выражения (`re.sub` с `re.DOTALL`), чтобы заменять текст строго между маркерами `// --- DATA START ---` и `// --- DATA END ---`.

## 2. БЭКЕНД И ПАРСИНГ (`auto_updater.py`)
* **Два источника**: Скрипт использует `watchdog`. 
  * Математику (TQS, AHT, оценки `0`/`0.5`/`1.0`) бери из `.xlsx` через `pandas`.
  * Тексты ("Тенденции", "Рекомендации") вытягивай из `.pdf` через `pdfplumber`, очищая их от переносов (`\n`).
* **Слияние**: Сопоставляй латиницу (Excel) и кириллицу (PDF) через словарь `NAME_MAP`.
* **Количество сотрудников**: В массиве должно быть ровно то количество сотрудников, которое указано в оценочном листе `.xlsx` за период. Никаких пустых дыр!

## 3. ФРОНТЕНД И ГРАФИКИ (Chart.js)
* **Progress Wave (Линейный график)**: График показывает динамику по периодам (точками). При выборе месяца (например, Март) он должен рендерить все доступные недели этого месяца (01-08, 09-15 и т.д.), соединяя точки в линию. **Обязательно** используй `spanGaps: true` и передавай `null` для недель без данных.
* **Режим «Сводка»**: Должен агрегировать данные — высчитывать среднее арифметическое TQS и AHT по каждому оператору за все недели.

## 4. МАТЕМАТИКА ТЕПЛОВОЙ КАРТЫ (Smart Tooltips)
Диагностика во всплывающих окнах считается строго по столбцу (критерию):
* Все `0` в критерии -> «Несоответствие СВП»
* 2 и более `0` в критерии -> «Критическая просадка»
* 1 `0` в критерии -> «Отсутствие критерия»
* Все `0.5` в критерии -> «Абсолютная недоработка»
* 2 и более `0.5` в критерии -> «Недоработка»
* 1 `0.5` в критерии -> «Критерий требует внимания»

## 5. БАЗА ЗНАНИЙ (Неприкасаемая зона)
* **Строго запрещено** удалять или ломать статические текстовые блоки в аккордеонах (спойлерах).
* В них зашиты фундаментальные инструкции: Регламенты QC v2.0, Механика оценки, Архитектура СВП, Правила CRM и Отработка возражений по ГК РУз.

Любое обновление кода или функционала должно соответствовать данным правилам!
