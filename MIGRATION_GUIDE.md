# Руководство по миграции проекта QC Dashboard v1.1 на новый ПК

В этом документе описаны пошаговые инструкции для бесшовного переноса проекта на новый ноутбук. Проект был спроектирован с учетом относительных путей, поэтому хардкода, привязанного к старой директории (`D:\Doc\...`), нет.

## Целевая структура

Новый путь к проекту: `C:\Проекты\QC Dashboard v1.1`

## Шаг 1: Установка необходимых программ
Перед запуском проекта на новом ноутбуке убедитесь, что установлены следующие программы:
1. **Python (версия 3.10 или выше)**
   - Скачайте с [официального сайта](https://www.python.org/downloads/).
   - **ВАЖНО:** При установке обязательно отметьте галочку **"Add Python to PATH"**.
2. **Docker Desktop (если вы используете бекенд и БД)**
   - Скачайте с [официального сайта Docker](https://www.docker.com/products/docker-desktop/).
   - Для работы Docker Desktop на Windows может потребоваться установка WSL2.
3. **Git (рекомендуется)**
   - Если вы используете систему контроля версий, [установите Git](https://git-scm.com/download/win).

## Шаг 2: Перенос файлов
1. Скопируйте всю папку проекта со старого ноутбука.
2. Вставьте её по пути `C:\Проекты\` и назовите папку `QC Dashboard v1.1`.
3. Убедитесь, что внутри лежат файлы `docker-compose.yml`, `auto_updater.py`, папки `backend`, `reports` и т.д.

## Шаг 3: Автоматическая настройка окружения
Для удобства настройки был создан скрипт, который сам создаст виртуальное окружение и скачает нужные библиотеки (зависимости).

1. Перейдите в папку `C:\Проекты\QC Dashboard v1.1`.
2. Найдите файл **`setup_env.bat`** и запустите его двойным кликом.
3. Дождитесь завершения работы скрипта. Он выполнит следующие действия:
   - Проверит наличие Python.
   - Создаст копию файла `.env.example` с именем `.env` (если его нет).
   - Создаст виртуальное окружение в папке `venv`.
   - Установит все необходимые библиотеки из файла `requirements.txt`.

## Шаг 4: Запуск проекта
Проект состоит из двух частей: Docker-контейнеры (бэкенд, база данных) и локальный скрипт парсинга отчетов (`auto_updater.py`).

### 1. Запуск серверной части (Docker)
Если вы используете Docker для БД и Backend:
1. Откройте терминал (Command Prompt или PowerShell) в папке проекта.
2. Введите команду:
   ```cmd
   docker-compose up -d
   ```
3. Docker скачает нужные образы и запустит базу данных PostgreSQL, FastAPI backend и Nginx.

### 2. Запуск авто-обновления данных (`auto_updater.py`)
Этот скрипт отслеживает файлы в папке `reports/` и генерирует данные для дашборда.
1. Откройте командную строку (cmd) в папке проекта `C:\Проекты\QC Dashboard v1.1`.
2. Активируйте виртуальное окружение:
   ```cmd
   venv\Scripts\activate
   ```
3. Запустите скрипт:
   ```cmd
   python auto_updater.py
   ```
4. Теперь, при добавлении новых отчетов XLSX или PDF в папку `reports/`, дашборд будет обновляться автоматически.

## Возможные проблемы (Troubleshooting)

- **`psycopg2` не устанавливается / ошибка компиляции C-кода**
  В `requirements.txt` указан `psycopg2` (или `psycopg2-binary`). Если скрипт настройки выдаёт ошибку при его установке, откройте терминал, активируйте окружение (`venv\Scripts\activate`) и введите вручную: `pip install psycopg2-binary`.

- **Скрипт `setup_env.bat` сразу закрывается**
  Откройте терминал `cmd.exe`, перейдите в папку `cd "C:\Проекты\QC Dashboard v1.1"` и запустите `setup_env.bat` вручную. Так вы увидите текст ошибки.

- **Docker не может поднять контейнеры из-за портов**
  Убедитесь, что порты `5432` (PostgreSQL), `8000` (Backend) и `80` (Nginx) не заняты другими приложениями на новом ноутбуке (например, локально установленным Skype или другим PostgreSQL сервером).

Если возникнут дополнительные сложности, вы можете обратиться ко мне или проверить конфигурацию в файле `.env`.
