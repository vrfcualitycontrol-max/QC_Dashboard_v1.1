## 1. Общая информация

- **Название проекта:** Dashboard QC — Аналитический дашборд Quality Control
- **Инициатор (заказчик):** QC отдел, Variant Retail Finance, Soft Collection Unit
- **Ответственные:** Команда разработки QC
- **Дата/версия ТЗ:** 1.2 (Апрель 2026)
- **Репозиторий:** https://github.com/vrfcualitycontrol-max/QC_Dashboard_v1.1

## 2. Цель и ожидаемый результат

- **Цель:** Готовое, корректно и стабильно работающее решение в виде аналитического дашборда в HTML-оболочке с автоматическим обновлением данных
- **Что считаем успехом:**
  - Автоматически обновляемый дашборд из источников (XLSX, PDF)
  - Корректное отображение данных в разрезе отдельных и совокупных периодов
  - Интерактивная фильтрация по месяцу, неделе, сотруднику
  - Визуализация показателей качества (TQS, AHT, СВП)
  - Персональные рекомендации на основе PDF-отчётов

## 4. Контекст и текущая проблема

- **Описание текущего процесса:** Dashboard содержит данные за периоды: февраль (полный цикл — 4 недели) и март (неполный цикл — 2+ недели). Парсер `auto_updater.py` (Python) обрабатывает файлы XLSX и PDF, дашборд автоматически подстраивает графики и индикаторы под обработанные данные.
- **Источники данных:**
  - XLSX: `Quality дд.мм.гггг - дд.мм.гггг.xlsx` (лист "Оценки звонков Soft Collection")
  - PDF: `Промежуточный отчет по сотрудникам SC за период дд-дд.мм.гг.pdf`
- **Боль/проблема:** Ручной анализ данных по сотрудникам, отсутствие визуализации трендов, сложность выявления проблемных зон в работе операторов.

## 5. Пользователи и сценарии (User stories)

- **Как руководитель QC**, я хочу видеть сводную тепловую карту по всей команде, чтобы быстро выявлять проблемные критерии.
- **Как руководитель группы**, я хочу видеть детализацию по каждому сотруднику, чтобы проводить персональные разборы.
- **Как оператор**, я хочу видеть свои показатели и рекомендации, чтобы улучшать качество работы.
- **Как аналитик**, я хочу фильтровать данные по периодам, чтобы анализировать динамику.

## 6. Функциональные требования

### 6.1 Основные функции

1. **Парсинг данных**
   - Чтение XLSX файлов из папки `reports/`
   - Чтение PDF файлов из папки `reports/`
   - Извлечение оценок по 9 критериям СВП
   - Извлечение рекомендаций из PDF

2. **Визуализация**
   - SVP Heatmap Pro — интерактивная тепловая карта с алгоритмом диагнозов
   - Динамика TQS — линейный график по периодам
   - Выработка по критериям — столбчатая диаграмма
   - Распределение оценок — круговая диаграмма (Pie Chart)
   - Общие показатели: сотрудники, звонки, средний TQS, AHT

3. **Фильтрация**
   - По месяцу (Февраль 2026, Март 2026, ...)
   - По периоду (неделя: 01-08, 09-15, 16-22, 23-28/31)
   - По сотруднику (все или конкретный)

4. **Детализация**
   - Клик на ячейку SVP Heatmap Pro → выезжающая панель
   - Pie Chart с распределением оценок (1.0 / 0.5 / 0.0)
   - Динамика по периодам (таблица)
   - Рекомендации из PDF

### 6.2 Роли и доступы

- **Роли:** Все пользователи имеют полный доступ (дашборд локальный)
- **Права:** Просмотр всех данных, фильтрация, детализация

### 6.3 UX/UI требования

- **Дизайн:** Современный, с матовым стеклом (glassmorphism), оранжевыми акцентами
- **Логотип:** VRF (New logo1.1.png) в нижней части меню
- **Шрифт:** Inter (Google Fonts)
- **Темы:** Тёмная (по умолчанию) / Светлая
- **Меню:** Сворачиваемое (240px → 70px), кнопка ☰ вверху
- **Адаптивность:** Десктоп (основной), планшет, мобильный (базовый)
- **Браузеры:** Chrome, Firefox, Edge, Safari (последние версии)

**Состояния:**
- **Loading:** Парсер обновляет данные (консоль)
- **Empty:** "Выберите период для отображения данных" (placeholder)
- **Error:** Сообщение об ошибке в консоли браузера

### 6.4 Правила и ограничения (Business rules)

- **Алгоритм диагнозов по столбцу:**

| Статус | Неделя (4 звонка) | Месяц (16 звонков) |
|--------|-------------------|---------------------|
| 🔴 Несоответствие СВП | Все «0» | Все «0» (10+) |
| 🔴 Критическая просадка | 2+ «0» | 6+ «0» |
| 🟠 Отсутствие критерия | 1 «0» | 2+ «0» |
| 🟡 Абсолютная недоработка | Все «0.5» | Все «0.5» (10+) |
| 🟡 Критическая недоработка | — | 10+ «0.5» |
| 🟡 Недоработка | 2+ «0.5» | 6+ «0.5» |
| 🔵 Критерий требует внимания | 1 «0.5» | 2+ «0.5» |
| 🟢 Полное соответствие | Все «1.0» | Все «1.0» |

- **AHT:** Отображается в формате ММ:СС (минуты:секунды)
- **Пороги AHT:** ≤3:30 (норма), 3:31-4:30 (предупреждение), >4:30 (критично)

## 7. Данные и интеграции

### Источники данных

- **XLSX файлы:**
  - Путь: `reports/Quality дд.мм.гггг - дд.мм.гггг.xlsx`
  - Лист: "Оценки звонков Soft Collection"
  - Колонки: ФИО Сотрудника, Длительность, 9 критериев СВП, Итоги (TQS)

- **PDF файлы:**
  - Путь: `reports/Промежуточный отчет по сотрудникам SC за период дд-дд.мм.гг.pdf`
  - Секции: "Отчет по сотруднику: [ФИО]"
  - Данные: Приоритет 0, Тенденции, Рекомендации

### Модель данных

```javascript
window.DASHBOARD_DATA = {
  "ФИО Сотрудника": {
    "periods": {
      "01-08 Фев 2026": {
        "tqs": 0.7975,
        "activity_count": 4,
        "scores": {
          "greeting": [1.0, 1.0, 1.0, 1.0],
          "ethics": [1.0, 0.5, 1.0, 0.5],
          // ... 9 критериев
        },
        "aht": 3.54
      }
    },
    "recommendations": "...",
    "trends": "..."
  }
}
```

## 8. Нефункциональные требования

- **Производительность:** Загрузка страницы < 3 сек (локальный сервер)
- **Надёжность:** Парсер обрабатывает все файлы в папке `reports/`
- **Безопасность:** Локальное использование, нет внешних API
- **Логирование:** Консоль браузера (ошибки), консоль парсера (INFO/WARNING/ERROR)
- **Локализация:** Русский язык

## 9. Аналитика и события

- **Трекаемые события:** Нет (локальный дашборд)
- **Метрики:** TQS, AHT, выработка по критериям, количество звонков

## 13. Риски и допущения

- **Риски:**
  - Изменение структуры XLSX/PDF файлов → парсер сломается
  - Большой объём данных → медленная загрузка HTML
- **Допущения:**
  - Файлы XLSX/PDF имеют стабильную структуру
  - Дашборд используется локально (нет нагрузки)
- **Зависимости:**
  - Python 3.x, pandas, openpyxl, pdfplumber
  - Chart.js (CDN), Font Awesome (CDN)
