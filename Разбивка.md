# Prompt: Превратить одностраничный лендинг в полноценный сервис с многостраничной архитектурой

## Роль
Ты — UX-архитектор, продуктовый аналитик и системный проектировщик веб-сервисов. Твоя задача — преобразовать существующий одностраничный лендинг (с декоративным боковым меню) в полноценный многостраничный сервис с логичной навигацией, страницами, подразделами и функциональными модулями.

## Цель
На основе структуры ниже:
- спроектировать архитектуру сервиса
- превратить боковое меню в навигацию между страницами
- определить страницы, подразделы и функции
- описать логику переходов
- предложить URL-структуру
- предложить информационную архитектуру
- определить тип контента для каждой страницы
- описать будущую масштабируемость

Ф = Функции

Тактические инструменты (ПР)

- Выставление требования (Ф)

## Задачи

### Шаг 1. Спроектировать архитектуру сервиса
Определи:
- Главные разделы (верхний уровень)
- Подразделы (второй уровень)
- Страницы функций (третий уровень)

Выведи в виде дерева:

Раздел  
→ Подраздел  
→ Страница функции  

---

### Шаг 2. Предложить структуру URL
Пример формата:

/analytics/operational-metrics  
/tools/b2c/objection-handling  
/regulations/qc/rules  

Сформируй URL для всех страниц.

---

### Шаг 3. Спроектировать боковое меню
Опиши:

- уровни вложенности
- поведение раскрытия
- активное состояние
- переходы между страницами
- breadcrumb навигацию

---

### Шаг 4. Определить тип страницы для каждой функции

Для каждой страницы укажи:

- Тип страницы (инструмент / база знаний / регламент / аналитика)
- Контент
- UI блоки
- Возможные интерактивные элементы
- Возможность масштабирования

---

### Шаг 5. Спроектировать UX сервиса

Опиши:

- логика переходов
- пользовательские сценарии
- переход между B2C и B2B
- быстрый доступ к инструментам
- поиск
- фильтрация
- закрепленные инструменты

---

### Шаг 6. Определить будущую масштабируемость

Опиши:

- добавление новых разделов
- добавление новых инструментов
- роли пользователей
- личный кабинет
- сохранение шаблонов
- аналитика использования

---

## Формат ответа

1. Архитектура сервиса (дерево)
2. Структура URL
3. Боковое меню
4. Страницы и их типы
5. UX логика
6. Масштабируемость
7. Рекомендации по превращению лендинга в сервис

Важно: Декомпозируй задачу, следуй пошагово.
Не допускай поломок функций. Предотврати эффект "одно лечим - другое калечим".
Если из файлов, которые я загружу, ты не сможешь что-то прочитать/просмотреть из-за ограничений — обязательно скажи об этом и предложи, как исправить.
